# Spec: A2A Actions

## Status

Implemented.

This spec defines the built-in `a2a.send` and `a2a.get_task` actions.

## Scope

`a2a.send` submits a message to a remote A2A agent and returns the Task or
Message it answers with. `a2a.get_task` reads one Task by ID. Both publish
structured JSON as step output. The remote agent owns task execution and
persistence; Dagu only submits and reads.

This spec covers:

- discovery of the Agent Card and selection of the JSON-RPC interface
- the `with` fields, the output shapes, and polling with `repeat_policy`
- credentials, origins, redirects, and masking
- error kinds, timeouts, cancellation, and the lost-response boundary
- recovery in a new run

This spec does not define:

- hosting A2A agents or any agent reasoning
- streaming, push notifications, task cancel or list, and extended cards
- the gRPC and HTTP+JSON bindings, and A2A protocol versions other than 1.0
- automatic reconciliation of tasks after a crash

## Goal

A deterministic DAG delegates work to a separately deployed agent, continues
with other steps, polls the task, and uses its artifacts, without an LLM
coordinator and without hand-written JSON-RPC.

## Behavior

The implementation uses the official Go SDK `github.com/a2aproject/a2a-go/v2`
for card decoding and the JSON-RPC calls, with Dagu's own HTTP client so the
rules below hold.

### Discovery

The Agent Card is read with one `GET` of `<agent_url>/.well-known/agent-card.json`
(an `agent_url` whose path already ends in `.json` is used as written). The card
must list `supportedInterfaces`. The first interface with
`protocolBinding: JSONRPC` and `protocolVersion` `1.0` is used. Its URL may
differ from the discovery URL in path and, when no `headers` are configured, in
origin. Other bindings on the card are ignored.

Each of these ends the step with kind `discovery` before any `SendMessage` or
`GetTask`: a card that is not JSON, a card without `supportedInterfaces` (an
A2A 0.3 card, which has a top-level `url`, is named as such), no JSONRPC
interface, JSONRPC only for other protocol versions, an advertised RPC URL that
is not an absolute https URL without user info, a card answered with a non-200
status other than 401, 403, or a redirect, and, when `headers` are set, an RPC
URL on another origin than `agent_url`. A card request answered with HTTP 401 or
403 ends with kind `auth`, and one answered with a redirect (3xx, which is never
followed) ends with kind `protocol`, as for any other request.

### with fields

Common fields:

| Field | Required | Meaning |
| --- | --- | --- |
| `agent_url` | yes | Absolute `https` URL of the agent. User info, a query string, and a fragment are rejected, so no credential can ride in the URL. |
| `headers` | no | Request headers; use `${SECRET}` references for credentials. `Content-Type`, `Accept`, `A2A-Version`, `Host`, and `Content-Length` are set by the client, and `Idempotency-Key` and `X-Idempotency-Key` would make Go's HTTP stack replay a dropped POST; all are rejected (case-insensitive). |
| `tenant` | no | Tenant sent with the request. Defaults to the tenant of the selected card interface. |

`a2a.send` fields: `message` (required text of one user message), `context_id`
(optional context to continue), `message_id` (optional `messageId`, see Message
IDs), and `return_immediately` (default `true`,
sent as the `returnImmediately` configuration; `false` asks the agent to
answer when the task ends, bounded only by the step timeout).

`a2a.get_task` fields: `task_id` (required) and `history_length` (optional
non-negative integer, or a reference that resolves to one).

Unknown fields fail validation. References such as `${A2A_URL}`,
`${params.PROMPT}`, and `${SEND.task_id}` are accepted at load time and the
resolved values are validated again before any request is made; the JSON schema
and the runtime accept the same forms. IDs and tenant must be at most 512
characters without control characters; header names must be HTTP tokens and
header values must not contain line breaks.

### Output

`a2a.send` with a Task answer:

```json
{"kind":"task","agent_url":"...","task_id":"task-1","context_id":"ctx-1","state":"working","status_message":null,"history":[],"artifacts":[],"sent_message_id":"..."}
```

With a direct Message answer: `kind` is `message`, with `message_id`,
`context_id`, `task_id` (empty when absent), `role`, `parts`, `text` (the text
parts joined by newlines), and `sent_message_id`. A Message needs no polling;
branch on `${SEND.kind}`. `a2a.get_task` writes the Task fields with
`kind: task`. `tenant` is included when one applies. `parts`, `history`, and
`artifacts` are the agent's JSON, including multipart artifacts.

`state` is `submitted`, `working`, `completed`, `failed`, `canceled`,
`rejected`, `input-required`, or `auth-required`. A remote state is data, not
an RPC failure: the step succeeds whatever the state. Only `completed` is
success for a workflow, so a later step must test it. With `repeat_policy`
(`repeat: until`, `condition: ${TASK.state}`) the task is polled until a
terminal or interrupted state; `on_limit: fail` fails the step when the limit
ends the loop first.

When the step sets `output` and the JSON is larger than the DAG's
`max_output_size` (1MB by default), the step fails with kind `output_limit`
instead of capturing a truncated value, and stdout carries only the error.
`a2a.get_task` with `output` refuses a response body over twice
`max_output_size` while reading it, with the same kind. For `a2a.send` the
message was already accepted, so the error carries `message_id`
and says that a retry can duplicate remote work. When the response is a Task,
the error names its `task_id`; read that task with `a2a.get_task`. When the
response is a direct Message, the error does not identify a task, and
`a2a.get_task` cannot recover it.

### Credentials and origins

`headers` apply to the Agent Card request and to the JSON-RPC request only when
its origin equals that of `agent_url`. An origin is scheme, host, and port, with the default port made explicit, so `https://h` and `https://h:443` are the same origin. A card that
advertises another origin is refused when `headers` are set; without `headers`
the advertised endpoint is used. Redirects are never followed and never carry
headers. Only `https` is used.

Because `headers` go to whatever origin `agent_url` names, a DAG that sends
credentials sets `agent_url` itself, for example in `env`, rather than taking
it from a parameter; otherwise whoever starts a run chooses where the
credentials go.

The step masks with `***`, in output and error messages: the value of a header
whose name contains `auth`, `cookie`, `key`, `token`, `secret`, or `password`
(case-insensitive) at any length; the part after the first space of such a
value, such as the token of `Bearer <token>`; and the JSON-escaped form of each.
Values of other headers, such as `X-Region`, are not masked, so ordinary data is
not rewritten. Only string values are masked: object keys and non-string JSON
values are never changed, so a credential an agent echoes as a JSON key is not
masked.
Values declared under `secrets` are also masked in step logs by Dagu.

### Errors

The step fails when the call fails. stdout is
`{"error": {"kind": "...", "message": "..."}}` and the step error starts with
`a2a.<action>: <kind> error:`. Text that the message quotes from the agent or
its Agent Card is cut to 1 KiB. Kinds:

| Kind | Meaning |
| --- | --- |
| `discovery` | The Agent Card is missing, malformed, or unusable (see Discovery). |
| `auth` | HTTP 401 or 403, or an A2A unauthenticated or unauthorized error. |
| `not_found` | The agent reports that the task does not exist: wrong `task_id`, agent, or tenant. |
| `remote` | Another A2A error answered by the agent. |
| `protocol` | A redirect, or a response that is not a valid A2A answer. |
| `transport` | A network failure, a response lost after the headers, or an HTTP status of 400 or more without an A2A error. |
| `timeout` | The step or DAG timeout elapsed. |
| `canceled` | The run was stopped. |
| `output_limit` | The result exceeds the output capture limit. |

Discovery and each request are bounded by the step's deadline. When the step
has no `timeout_sec` (and no DAG timeout reaches it), discovery and the call
together are bounded by a default of 60 seconds and end with kind `timeout`;
set `timeout_sec` for longer, for example with `return_immediately: false`. Canceling the
local run does not cancel the remote task.

### Message IDs

The submitted `messageId` is `with.message_id` when set, exactly as resolved
(no trimming or hashing). It may use references, such as
`${DAG_RUN_ID}-delegate` to keep one ID across attempts. It must be 1 to 512
characters without control characters; an explicitly set empty value is a
validation error rather than a fallback to the default. The JSON schema and
load-time validation check literal values (a value holding a reference is
checked once resolved), and runtime validation checks the resolved value
before anything is dialed.

Otherwise it is a UUIDv5, in a fixed Dagu namespace, over the JSON array
`[attempt ID, step name, repeat index, message text, foreach item]`. JSON
encoding keeps field boundaries unambiguous. The repeat index is `0` without a
`repeat_policy`; the foreach item is empty outside a foreach body. A step
`retry_policy` retry keeps all of them, so it sends the same ID. The next
`repeat_policy` iteration, a Dagu retry of the run (a new attempt), another
step, or another message sends a new one. `sent_message_id` in the output and
`message_id` in the error output always equal the submitted ID.

### Lost responses and retries

`a2a.send` sends `SendMessage` exactly once per step execution and never retries. When a
failure leaves open whether the agent received the message (a dropped
connection, a response lost mid-body, a malformed answer, a 5xx status, a
timeout, or a cancellation), the message says `Outcome unknown` and the error
output carries `message_id`, the ID of the submitted message. A `retry_policy`
retry resends the same `messageId`, so an agent that deduplicates by it returns
the existing task and the work runs once; an agent that does not deduplicate
can still run it twice. Dagu neither replays the HTTP request itself nor
assumes the agent deduplicates. A Dagu retry of the run uses a new attempt ID
and so a new message, and a `repeat_policy` on `a2a.send` submits a new message
on each iteration; both can duplicate remote work. Poll with `repeat_policy` on
`a2a.get_task` instead. Rejections
that prove the agent did not accept the message (401, 403, an A2A error) do not
carry this note.

### Recovery

Persist `task_id` and `tenant` from the `a2a.send` output, for example as DAG
outputs. A new run starting at `a2a.get_task` with these values and the same
`agent_url`, set in its DAG as described under Credentials and origins, reads
the same task and sends nothing; credentials come from Dagu secrets again. A crash after the agent accepted a message but before
`task_id` was saved loses the task ID; this action does not reconcile it.
